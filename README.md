# ایجنت تعمیر فلش — فاز ۱: عیب‌یابی و گزارش

نرم‌افزار ویندوزی که با مدل هوش مصنوعیِ انتخابی خود کاربر (نشانی پایه + کلید + نام مدل) فلش‌های خراب را عیب‌یابی می‌کند. سند طراحی کامل در فایل نقشه MVP آمده است و این مخزن پیاده‌سازی فاز ۱ همان سند است: فقط عیب‌یابی و گزارش، بدون هیچ نوشتن روی فلش.

## وضعیت فاز ۱

پیاده‌سازی‌شده و تست‌شده:

- هر ۱۴ ابزار فاز ۱ (۹ ابزار تشخیص گروه الف + ۵ ابزار نشست گروه هـ)، همه فقط‌خواندنی و همه پشت دروازه ایمنی
- موتور تشخیص قطعی بر اساس درخت تصمیم سند؛ مدل فقط توضیح می‌دهد و هرگز عدد یا دسته خرابی اختراع نمی‌کند
- لایه دسترسی واقعی ویندوز برای خواندن مشخصات، چیدمان پارتیشن و نمونه‌خوانی سکتوری از فلش واقعی
- بک‌اند مجازی با ۶ نمونه خرابی ضبط‌شده (سالم، فایل‌سیستم خام، ظرفیت صفر، ظرفیت جعلی، نواحی مرده، جدول پارتیشن خراب) تا کل مسیر بدون سخت‌افزار تست شود
- دروازه ایمنی با قوانین کدی: ممنوعیت دیسک سیستمی، اجبار تأیید ثبت‌شده برای ابزارهای مخرب، بررسی دوباره شماره سریال در لحظه اجرا
- اتصال مدل سازگار با رابط استاندارد گفتگو، با فراخوانی ابزار بومی و حالت جایگزین ساخت‌یافته برای مدل‌های بدون فراخوانی ابزار؛ ذخیره کلید روی ویندوز فقط با سازوکار محافظت داده خود ویندوز
- رابط خط فرمان کامل + اسکلت رابط گرافیکی ویندوزی که همان کتابخانه‌ها را صدا می‌زند

پیاده‌سازی‌نشده (طبق نقشه، برای فازهای بعد):

- ابزارهای نوشتن و تعمیر استاندارد (فاز ۲)، فلش فریمور (فاز ۴، خانواده‌به‌خانواده)
- نگاشت دقیق حرف درایو به دیسک فیزیکی در بک‌اند ویندوز (فاز ۱٫۵)

## اجرا

پیش‌نیاز روی ویندوز: دات‌نت ۸. برای دسترسی به فلش واقعی، اجرا با دسترسی مدیر سیستم لازم است.

```powershell
# فهرست دستگاه‌ها (روی ویندوز = فلش‌های واقعی سیستم)
.\flashrepair.exe devices

# عیب‌یابی کامل یک دستگاه + ذخیره گزارش
.\flashrepair.exe diagnose --device <DEVICE_ID> --out reports

# اجرای نمایشی روی نمونه‌های مجازی خراب
.\flashrepair.exe demo

# تست اتصال مدل خودتان (فایل model.json با baseUrl و model و apiKey — یا متغیر محیطی FRA_API_KEY)
.\flashrepair.exe model-test --model model.json
```

## ساخت از سورس

```powershell
.\build.ps1
```

سولوشن اصلی (کتابخانه‌ها + خط فرمان + تست‌ها) روی هر سیستم‌عاملی ساخته می‌شود و هیچ بسته خارجی ندارد. سولوشن ویندوزی، پروژه رابط گرافیکی را هم اضافه می‌کند و فقط روی ویندوز ساخته می‌شود.

## تست‌ها

dotnet build FlashRepairAgent.sln -c Release

## ساختار

- پوشه Core: قرارداد ابزار، مدل‌های داده، کاتالوگ کنترلر و بانک فراداده فریمور
- پوشه Tools: چهارده ابزار فاز ۱ + سازنده گزارش
- پوشه SafetyGate: دروازه ایمنی و سیاست ریسک
- پوشه ModelProvider: کلاینت مدل و ذخیره امن کلید
- پوشه Agent: موتور تشخیص، گرداننده نشست و لایه توضیح مدل
- پوشه‌های Backends: دسترسی واقعی ویندوز و شبیه‌ساز مجازی
- پوشه‌های Cli و App: میزبان خط فرمان و رابط گرافیکی ویندوزی
- پوشه samples: نمونه‌های خرابی ضبط‌شده + یک گزارش نمونه واقعی تولیدشده توسط برنامه
